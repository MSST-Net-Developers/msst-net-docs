## 概述

任何人都可以部署一台**自托管中转服务器**，供自己和朋友的房间使用。

自托管中转与官方中转是同一个程序，区别在于：

| | 官方中转 | 自托管中转 |
|---|---|---|
| 运营者 | MSST-Net | 任何人 |
| 是否公开列出 | 是，所有设备都可自动选用 | 否 |
| 如何使用 | 自动选择或在设置中指定 | 房主建房时粘贴**连接串**，指定为房间中转 |
| 服务范围 | 所有设备 | 只为指定了它的房间转发 |
| 向协调服务器认证 | 预共享密钥 | 中转私钥（质询-应答） |

房间如何使用自托管中转，请参考：[《房间中转》](/connect/spaces/room_relay)

---

## 准备工作

- 一台有**公网地址**的服务器（公网 IP 或解析到公网 IP 的域名）
- 开放一个 **UDP** 端口（下文以 `7000` 为例）
- 中转服务器程序 `msstnetRelay31x`（见下文 [下载中转服务器](#下载中转服务器)）

> 中转地址不能是内网地址：私有地址、回环地址、链路本地地址、IPv6 唯一本地地址和运营商级 NAT 地址（`100.64.0.0/10`）都会被拒绝。客户端同样会拒绝解析到这些地址的房间中转。

## 配置

首次运行时，若配置文件不存在，程序会自动创建一份默认配置（权限 0600）：

```bash
./msstnetRelay31x -config config.yaml
```

将其修改为自托管模式：

```yaml
node:
  addr: relay.example.com:7000      # 客户端访问本中转的公网地址，会写入连接串
relay:
  bind: "[::]:7000"
  mode: self_hosted
  register_auth: required           # 自托管模式下必须为 required（也是默认值）
  password: ""                      # 可选：中转接入密码
  require_room_password: true       # 默认开启：只为设有房间密码的房间服务
discovery:
  auth_key_file: relay_discovery.key  # 中转私钥，认证登记也使用它
control:
  server_url: https://coord.msst-net.msst2031.cn   # 协调服务器地址，必须为 https
  # 自托管模式下不能设置 relay_secret
```

以下情况中转会拒绝以自托管模式启动：

- `register_auth` 不是 `required`
- 设置了 `control.relay_secret`（官方中转的密钥不应出现在第三方机器上）
- `server_url` 不是 `https` 地址
- `node.addr` 不是公网的 `主机:端口`

### 中转接入密码

设置 `relay.password` 后，房主在建房时必须提供该密码才能指定这台中转；其他成员加入房间时不需要。

- 密码不会写入日志，也不会离开本机：中转只向协调服务器提交密码的 Argon2id 校验值
- 设置了密码时，请保持配置文件权限为 `0600`，否则中转会发出警告
- 修改密码后需重启中转生效；已经创建的房间不受影响

### 要求房间密码

`relay.require_room_password` 默认开启：协调服务器会拒绝为指定了本中转、但没有设置房间密码的房间建房。

这样可以防止"拿到房间号的任何人都能进入房间并使用你的中转"。若确实需要服务无密码房间，可以显式关闭。

## 连接串

中转启动时会打印**连接串**，也可以随时查看：

```bash
./msstnetRelay31x -config config.yaml -print-link
```

连接串格式：

```text
msst-relay://<node.addr>#<中转公钥>[?pw=1]
```

- 设置了中转接入密码时，末尾带有 `?pw=1`，客户端会据此提示输入密码
- 连接串中包含中转的公钥：即使有人在同一地址部署了另一台中转，没有对应的私钥也无法冒充

将连接串发给房主即可。房主在建房时选择 **自托管中转服务器…** 并粘贴连接串。

::: warning 请妥善保管密钥文件
`discovery.auth_key_file`（默认 `relay_discovery.key`）保存着中转的私钥，是这台中转的身份。若首次运行时不存在，会自动创建。

请将它与配置文件一同备份；更换密钥后连接串会改变，需要重新分发。
:::

## 运行

```bash
./msstnetRelay31x -config config.yaml
```

启动后，中转会自动向协调服务器登记，并每 10 秒发送一次心跳：

- 登记成功前，中转照常转发，但房主还不能指定它
- 协调服务器重启或心跳失败时，中转会自动重新登记（退避 5 秒至 5 分钟）
- 登记失败时，日志中会给出协调服务器返回的错误码，如 `relay_unsupported`、`key_proof_invalid`

中转的运行状态以统计日志的形式定期输出（默认每 60 秒一行），没有管理接口。

## 自托管中转的转发规则

- 只转发**已在本中转完成认证登记**的成员发出的数据，外人无法把它当作开放转发器使用
- 只接受认证登记：没有设备私钥的人无法以别人的设备 ID 登记
- 任何人都可以 ping 它（有速率限制），客户端会在使用前检查中转是否可达
- 3.1.6 起客户端的游戏发现在加密隧道内传输，像普通数据一样经中转转发；中转仍为 3.1.5 及以前的客户端提供旧的游戏发现分发，只服务指定了本中转的房间

## 隐私与安全

自托管中转的运营者**能够看到**：

- 房间成员的设备 ID 与公网地址
- 流量的大小与时序
- 仅限 3.1.5 及以前的客户端：游戏发现数据的内容（如 Minecraft 服务器的 MOTD）

**无法做到**：

- 读取或篡改经 WireGuard 加密的通信内容（3.1.6 起包括游戏发现）
- 冒充房间成员发送数据，或冒充 3.1.6 客户端的房间成员发送游戏发现
- 让成员向内网地址发送流量（客户端只接受公网地址的房间中转）

恶意的中转最多只能丢弃或延迟数据包。此时成员的客户端会判定房间中转不可用，自动回退到各自的偏好中转，房间仍可继续使用。

## 资源限制

主要的默认限制（均可在 `config.yaml` 中调整）：

| 配置项 | 默认值 | 说明 |
|---|---|---|
| `relay.max_sessions` | 65536 | 最多同时登记的设备数 |
| `relay.session_ttl` | 120s | 设备登记在无保活时的过期时间 |
| `discovery.sender_rate` | 10/s | 每台设备的游戏发现发送速率（仅旧版客户端的游戏发现） |
| `discovery.max_fanout` | 256 | 每个发现包最多投递的成员数（同上） |
| `log.stats_interval` | 60s | 统计日志间隔，0 表示关闭 |
