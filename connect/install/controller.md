## 控制器的作用

客户端控制器用于管理 **MSST-Net 客户端核心**。

其主要功能包括：

- 查看本机与核心的连接状态
- 创建、加入和退出房间
- 管理防火墙规则、权限组和访问记录
- 处理交互式授权请求
- 执行接入认证
- 修改设备名称与助记符
- 管理自定义域名
- 查看日志与诊断信息

控制器本身**不负责网络连接功能**，也不会自行做出任何网络或授权决定：它展示的所有状态都来自客户端核心。关闭控制器不会影响网络连接。

---

## 控制器类型

MSST-Net 3.1 的图形控制器共用同一套界面，另有一个命令行控制器（3.1.8 起），按运行方式分为四种：

| 类型 | 平台 | 连接核心的方式 | 远程管理 |
|---|---|---|---|
| 桌面版 | Windows / Linux / macOS | 本机 IPC | 否 |
| 移动版 | Android | 内置核心 | 否 |
| WebUI 版 | 服务器 / 无桌面设备 | 本机 IPC，经 HTTPS 提供给浏览器 | 是 |
| 命令行版（`msst-net-cli`） | Windows / Linux / macOS | 本机 IPC，在终端中运行 | 否（可经 SSH 使用） |

### 功能差异

| 功能 | 桌面版 | 移动版 | WebUI 版 | 命令行版 |
|---|---|---|---|---|
| 规则向导与权限组管理 | 支持 | 不支持（可从授权请求、访问记录、房间成员添加规则） | 支持 | 支持（`rules`、`groups` 命令） |
| 编辑永久规则 | 全部内容 | 仅备注与启用状态 | 全部内容 | 全部内容（`rules edit`） |
| 更新提醒 | 顶部提示 + 关于页 | 只检查应用自身 | 顶部提示 + 关于页 | `check-update` 命令 |
| 为房间成员添加规则 | 支持（右键） | 支持（长按） | 支持 | 支持（`rules add --device`、`--room-members`） |
| 交互式授权 | 对话框 + 系统通知 | 对话框 + 带操作按钮的通知 | **不支持** | **不支持** |
| 访问密码与 IP 白名单 | — | — | 必需 | — |
| VPN 服务控制 | — | 支持 | — | — |
| 分应用代理 | — | 支持 | — | — |
| 仅 Linux 的网络选项（DNS 配置模式、其他 VPN 相关开关） | 支持 | 不显示（内置的 Android 核心不使用这些选项） | 支持 | 支持 |

## 界面导航

图形控制器包含以下页面：

| 页面 | 内容 |
|---|---|
| 首页 | 核心状态、接入认证、创建 / 加入房间、当前房间成员、本机标识与 ezPlay 主机名 |
| 防御 | 防火墙规则、Ping 开关、权限组管理、访问记录 |
| 域名 | 自定义 `.net.msst2031.cn` 命名空间与 DNS 记录（需完成认证） |
| 设置 | 设备名与助记符、诊断与调试、高级网络选项 |
| 关于 | 版本与协议信息、更新检查结果 |

## 桌面版

桌面版适用于具备桌面环境的设备（Windows / Linux / macOS），需要另外安装并运行客户端核心。

特点：

- 本地图形界面，支持系统托盘
- 交互式授权请求以系统通知提醒（Linux 使用原生桌面通知）

推荐给普通桌面用户使用。

---

## 移动版

移动版适用于 Android 设备。

特点：

- 原生移动端界面，适配手机等小屏幕
- **内置客户端核心**，无需单独安装核心组件
- 通过系统 VPN 服务接入，首页可以启动、休眠、恢复或停止 VPN 服务
- 支持"始终开启的 VPN"以及"屏蔽未使用 VPN 的连接"
- 支持**分应用代理**：在 **设置 → 分应用代理** 中选择不经过 MSST-Net 的应用
- 控制器界面未打开时，也会收到访问请求通知

> 从 3.0.x 升级时，设备身份保存在应用自己的数据目录中，升级后设备 ID 与虚拟 IP 保持不变。

---

## WebUI 版

WebUI 版适用于无桌面环境或需要远程管理的设备，通过浏览器访问。

详见：[《WebUI 远程管理》](/connect/install/webui)

## 命令行版

命令行控制器 `msst-net-cli` 在运行核心的设备上，以终端命令提供与 WebUI 版相同的功能，适合没有图形界面、又不需要从浏览器远程管理的设备（也可以经 SSH 使用）。它由普通用户直接运行，不是服务；权限与桌面版相同（见下文 [访问权限](#访问权限)）。

使用客户端安装器时选择控制器 **命令行**（`--controller cli`），即可直接运行 `msst-net-cli`；也可以从控制器的发布页下载 `msst-net-controller-cli-<系统>-<架构>`，改名为 `msst-net-cli` 后手动使用。

```bash
msst-net-cli --help          # 全部命令
msst-net-cli status          # 连接状态、本机身份、房间
msst-net-cli watch           # 持续显示状态变化（Ctrl-C 退出）
msst-net-cli room create 联机房 --password      # 创建带密码的房间（密码在终端中输入，不回显）
msst-net-cli room join space-1a2b3c4d           # 加入房间（需要密码时会提示输入）
msst-net-cli rules add --device pc.alice --service minecraft-java   # 添加规则
msst-net-cli settings set keepalive 15          # 修改网络设置
```

| 命令 | 作用 |
|---|---|
| `status` / `watch` | 总览 / 持续显示状态变化 |
| `nodes` | 已知节点及其路径 |
| `room` | 房间：`show`、`create`、`join`、`leave` |
| `rules` | 防火墙规则：`list`、`add`、`edit`、`enable`、`disable`、`comment`、`delete`、`clear` |
| `groups` | 权限组 |
| `services` | 可用于规则的服务模板 |
| `access` | 访问记录，以及据此 `allow-once`、`allow`、`deny`、`revoke` |
| `identity` | 查看或修改设备名与助记符 |
| `login` | 接入认证：显示认证网址与验证码，在浏览器中完成 |
| `reregister` | 向协调服务器重新注册本设备 |
| `settings` | 网络设置：`show`、`set` |
| `relays`、`paths`、`traffic`、`endpoints`、`diag-ping`、`logs` | 诊断（见 [《诊断工具》](/connect/troubleshoot/diagnostics#命令行诊断)） |
| `dns` | 自定义 DNS 命名空间与记录 |
| `check-update` | 检查核心与控制器是否有新版本（核心未运行时只检查控制器） |
| `raw` | 发送任意 IPC 请求（诊断用） |

使用说明：

- 每条命令会先连接核心并同步状态（`--timeout`，默认 10 秒），执行后退出；`--json` 输出核心返回的原始数据
- 规则、权限组、DNS 记录和访问记录可以用 ID 的唯一前缀指代
- 删除、清空、覆盖全部端口的规则等操作会要求确认；`--yes` 跳过确认。没有终端时（例如在脚本中）不加 `--yes` 会直接拒绝这类操作
- 房间密码与中转接入密码只写 `--password`、`--relay-password` 时在终端中输入，不回显，也不会留在命令历史里
- 与 WebUI 版一样**不处理交互式授权**：访问请求需要在桌面版或移动版中处理，否则 60 秒后超时
- 时间按系统时区显示
- 退出码：`0` 成功，`1` 操作失败，`2` 输入有误或需要确认，`3` 无法连接核心或版本不兼容

> 用 Docker 运行核心、命令行控制器装在主机上时，容器中的核心只接受 root 的连接，请使用 `sudo msst-net-cli`。

## 连接客户端核心

桌面版、WebUI 版与命令行版通过本机 IPC 连接客户端核心：

| 平台 | 默认 IPC 路径 |
|---|---|
| Linux | `$XDG_RUNTIME_DIR/msst-net/ipc.sock`，其次 `/run/msst-net/ipc.sock` |
| macOS | `$TMPDIR/msst-net/ipc.sock`，其次 `/var/run/msst-net/ipc.sock` |
| Windows | `\\.\pipe\msst-net-ipc` |

可以通过环境变量 `MSST_IPC_PATH` 指定其他路径。

### 访问权限

客户端核心是特权进程，因此并不是能打开 IPC 套接字就能操作核心。核心会检查连接方的系统用户，并授予以下角色之一：

| 角色 | 授予对象 | 权限 |
|---|---|---|
| 管理（admin） | 运行核心的用户、root / LocalSystem、通过 `sudo` 启动核心的用户、本地用户组 `msst-net`（Windows 为 `MSST-Net Administrators`）的成员、以管理员身份运行的程序（Windows） | 全部操作 |
| 只读（viewer） | 其他拥有本地登录会话的用户 | 只能查看状态 |
| — | 其他用户 | 拒绝连接 |

客户端安装器会创建上述用户组，并把安装用户加入其中（Windows 上为当前桌面登录的用户）。

当核心以 root / 系统服务运行时，请将日常使用的账号加入管理员组，以获得管理权限。Linux / macOS：

```bash
sudo groupadd -f msst-net
sudo usermod -aG msst-net $USER
```

Windows（以管理员身份运行命令提示符）：

```bat
net localgroup "MSST-Net Administrators" <用户名> /add
```

用户组成员资格在每次连接时检查，加入后**重新打开控制器**即可，无需重启核心，也无需重新登录系统。

> 3.1.9 及以前的 Windows 核心只认登录时的组成员关系，加组后需要注销并重新登录 Windows。

以只读角色连接时，控制器会显示只读提示，修改操作不可用。

### 版本兼容

控制器会在连接时与核心协商 IPC 协议版本，并在 **关于** 页面显示双方的协议版本。核心版本较旧、缺少某些功能时，控制器会禁用对应功能并说明原因。

## 更新提醒

3.1.10 起，控制器会检查是否有新版本：

- 启动约 10 秒后检查一次，之后每天一次（失败时每小时重试）
- 同时访问 GitHub 与 Gitee 上核心和控制器的最新**正式版**，采用先返回的一方；只读取发布清单中的版本号
- 与正在运行的核心（3.1.10 起会报告自己的版本）和控制器比较；核心版本较旧、不报告版本时只比较控制器

发现新版本时，桌面版和 WebUI 版在顶部提示，例如"发现新版本：Core 3.1.10 → 3.1.11"，并给出客户端安装器的下载链接；**关于** 页面也会显示检查结果。控制器不会自行更新：请下载最新的客户端安装器，以管理员身份运行（Linux / macOS：`sudo`）并选择 **升级**。

- 关闭提示后，本次运行期间不再提醒，出现更新的版本时会再次提醒
- **移动版**内置核心，只检查应用自身的版本，提示中给出 APK 的下载链接，下载与本机架构对应的 APK（多数手机为 `aarch64`）覆盖安装即可
- **命令行版**不自动检查，运行 `msst-net-cli check-update` 即可
- 不需要检查更新时，为控制器设置环境变量 `MSST_UPDATE_CHECK=0`

## 如何选择控制器

普通桌面用户：

建议使用 **桌面版**。

服务器用户：

需要从浏览器远程管理时，建议使用 **WebUI 版**；只在本机终端或经 SSH 管理时，可以使用 **命令行版**。

移动端用户：

建议使用 **移动版**。
