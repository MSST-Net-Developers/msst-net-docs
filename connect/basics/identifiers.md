## 主体类型

在 MSST-Net 中，**主体**是网络中的基本标识单位。

目前，MSST-Net 支持以下主体类型：

- 用户
- 设备
- 房间（space）

每个主体都具有独立的标识符，用于识别、管理和访问控制。

---

## 用户

**用户**是一类基本主体，用于标识同一用户关联的所有设备。

对于**认证用户**，用户 ID 由 MSST 联合认证平台账号推导而来，登录到同一账号的所有设备都会关联到同一用户主体。

对于**免认证用户**，用户 ID 由当前设备的密钥推导而来，因此该用户通常只关联当前设备。

用户主体主要用于统一管理多个设备的身份关系。

详见：[《接入认证》](/connect/basics/authentication)

---

## 设备

**设备**是一类基本主体，用于标识唯一的客户端实例。

每个接入到 MSST-Net 的客户端实例都会对应一个独立的设备主体。

当前版本中，MSST-Net 的访问控制主要以**设备**作为最小控制单位。

---

## 房间

**房间**是临时性的主体，用于标识一次房间模式会话。

房间 ID（`space-{8位十六进制}`）在创建时生成，可用于访问控制规则中匹配当前房间成员。

详见：[《房间模式》](/connect/spaces/room_space)

---

## 标识符体系

每个主体都具有以下三类标识符：

- ID（唯一标识符）
- 助记符（可读标识符）
- 显示名称（展示标识符）

不同类型的标识符适用于不同场景。

---

## ID

**ID** 是主体的唯一标识符。

每个主体的 ID 在创建后即固定，不可修改。

所有其他标识符都建立在 ID 的基础上。

### 格式规则

用户 ID：

```text
user-{8位十六进制}
```

设备 ID：

```text
device-{8位十六进制}
```

房间 ID：

```text
space-{8位十六进制}
```

### 示例

用户 ID：

```text
user-1a2b3c4d
```

设备 ID：
```text
device-a7f29b3e
```

房间 ID：
```text
space-7e3a9f12
```

### 来源

- **设备 ID** 由设备公钥的 SHA-256 哈希前 4 字节推导而来。协调服务器会校验设备 ID 与公钥是否匹配，要求设备证明自己持有对应的私钥，并将首次登记的公钥与设备 ID 绑定。客户端收到其他设备的公钥时也会重新校验，公钥与设备 ID 不对应的设备会被忽略
- **用户 ID**：认证用户由账号推导；免认证用户由设备公钥推导（同样会被协调服务器和其他客户端校验）
- **房间 ID** 在创建房间时随机生成

### 特性
- 全局唯一
- 不可修改
- 可用于规则引用
- 推荐用于精确标识主体
- 防火墙规则在保存时一律使用 ID

## 助记符

**助记符**是主体的人类可读标识符。

助记符主要用于简化引用、生成可读名称以及构建规则。

助记符允许用户修改，但其唯一性取决于主体类型与作用域。

### 助记符的分类

MSST-Net 当前支持以下助记符类型：

- 用户助记符
- 设备助记符
- 组合助记符

### 用户助记符

用户助记符用于标识用户主体。

用户助记符在全局范围内唯一。

#### 示例

```text
abjust
```

#### 特性
- 全局唯一
- 可修改（认证用户的用户助记符取自账号用户名，由协调服务器管理，在本地修改不会生效）
- 可用于规则引用
- 适用于标识用户

### 设备助记符

设备助记符用于标识设备主体。

设备助记符仅在同一用户作用域内保证唯一。

这意味着：

- 不同用户可以使用相同设备助记符
- 同一用户下出现重复设备助记符将触发冲突处理

#### 示例

```text
archlinux
```

设备助记符可以在控制器的 **设置** 页面修改（命令行控制器：`msst-net-cli identity --handle <助记符>`）；留空时使用设备 ID。

### 组合助记符

由于设备助记符不保证全局唯一，因此 MSST-Net 提供 **组合助记符** 用于唯一标识设备。

组合助记符格式如下：

```text
{device}.{user}
```

其中：

- {device} 为设备助记符
- {user} 为用户助记符

组合助记符在全局范围内唯一。

#### 示例

```text
archlinux.abjust
```

#### 特性
- 全局唯一
- 可用于规则引用
- 用于跨用户唯一标识设备
- 由用户助记符与设备助记符组合生成

### 冲突处理
当助记符发生冲突时，系统会自动追加递增编号：

```text
example
example-1
example-2
```

冲突处理规则适用于同一作用域内的助记符。

例如：

- 用户助记符在全局范围内处理冲突
- 设备助记符在同一用户作用域内处理冲突

### 格式规则

助记符仅允许以下字符：

- 小写字母（a-z）
- 数字（0-9）
- 横杠（-）

组合助记符中的 . 仅作为分隔符使用。

助记符本身不包含任何类型前缀。

### 用途

助记符主要用于：

- 生成人类可读的 MSST-Net ezPlay 主机名
- 在规则中进行简化引用（创建规则时会解析为 ID）
- 快速定位主体

组合助记符主要用于：

- 唯一标识设备
- 跨用户引用设备

| 类型    | 全局唯一     | 可修改 | 可用于规则 | 主要用途   |
| ----- | -------- | --- | ----- | ------ |
| 用户助记符 | 是        | 是   | 是     | 标识用户   |
| 设备助记符 | 否（用户内唯一） | 是   | 是     | 标识设备   |
| 组合助记符 | 是        | 间接  | 是     | 唯一标识设备 |

## 显示名称

**显示名称**是主体对外展示的名称。

显示名称主要用于界面展示和用户识别。

显示名称允许重复，不保证唯一。

### 特性
- 不保证唯一
- 可修改
- 不可用于规则引用
- 用于界面展示（设备显示名称会展示给房间内的其他成员）

### 示例

设备显示名称：

```text
Abjust 的电脑
```

未设置设备显示名称时，使用由用户 ID 生成的默认名称，例如用户 ID 为 `user-1a2b3c4d` 时：

```text
用户1a2b3c4d的设备
```

设备显示名称可以在控制器的 **设置** 页面修改（命令行控制器：`msst-net-cli identity --name <名称>`）；修改后会同步到协调服务器（若暂时无法连接，会在下次连接时同步）。

## 标识符对比

| 标识符  | 唯一性       | 可修改 | 可用于规则 | 主要用途 |
| ---- | --------- | --- | ----- | ---- |
| ID   | 是         | 否   | 是     | 精确标识 |
| 助记符  | 否（自动处理冲突） | 是   | 是     | 简化引用 |
| 显示名称 | 否         | 是   | 否     | 对外展示 |
