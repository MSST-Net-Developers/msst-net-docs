## 总览

MSST-Net 由以下几部分组成：

| 组件 | 运行位置 | 职责 |
|---|---|---|
| 客户端核心（Core） | 每台接入设备 | 虚拟网卡、加密、选路、防火墙、DNS、游戏发现 |
| 客户端控制器（Controller） | 每台接入设备（或通过浏览器） | 图形界面，向核心发送操作请求、展示核心状态 |
| 协调服务器（Coordinator） | MSST-Net 服务端 | 设备登记、地址分配、房间、ezPlay 主机名、接入认证 |
| 中转服务器（Relay） | MSST-Net 服务端，或自行部署 | 在无法直连时转发加密后的数据 |
| MSST 联合认证平台 | MSST 服务端 | 账号与身份认证 |

```text
  控制器 ──IPC──► 客户端核心 ──WebSocket / HTTPS──► 协调服务器 ──► MSST 联合认证平台
                     │
                     ├──UDP（直连）────────────────► 对端设备
                     └──UDP（中转）──► 中转服务器 ──► 对端设备
```

---

## 客户端核心

客户端核心是运行在每台设备上的**特权进程**，是本机网络状态的唯一权威来源。

它负责：

- 创建虚拟网卡（默认名称 `msst0`）并配置虚拟地址
- 用 WireGuard 加密与对端之间的全部数据
- 选择连接路径（直连或中转）
- 执行防火墙规则与交互式授权
- 在本机解析 `*.msst.net` 域名
- 在房间内转发游戏的局域网发现广播

即使控制器关闭，核心也会持续运行，网络连接不受影响。

核心使用的本机端口：

| 端口 | 用途 |
|---|---|
| UDP 21031 | 数据通道（直连与中转） |
| UDP 21032 | 游戏发现 |
| UDP 127.0.0.1:21053（Windows 为 127.0.0.1:53） | 本机 DNS 解析 |
| TCP 9100 | Prometheus 指标 |

## 客户端控制器

控制器是**非特权**的图形界面程序，通过本机 IPC 与核心通信：

- Linux / macOS：Unix 域套接字
- Windows：命名管道 `\\.\pipe\msst-net-ipc`

控制器只负责展示核心报告的状态、把用户的操作转交给核心，**不直接修改任何网络状态**。

控制器重新打开或重新连接时，会先向核心读取完整状态，再接收后续的变更通知，因此不会因为关闭过控制器而显示过时的信息。

详见：[《控制器说明》](/connect/install/controller)

## 协调服务器

协调服务器是 MSST-Net 的控制面，负责：

- 设备上线、登记与在线状态
- 由设备 ID 推导虚拟 IP 地址，并处理地址冲突
- 分配 ezPlay 主机名，提供 `*.msst.net` 解析数据
- 房间的创建、加入、成员同步与房间密码校验
- 对接 MSST 联合认证平台（OIDC 设备授权流程），以及签发访客凭据
- 登记中转服务器并向客户端公布可用的官方中转
- 管理自定义 `.msst.net` 命名空间

客户端核心与协调服务器之间通过 WebSocket 保持长连接，并使用 HTTPS 接口完成登记、建房等操作。

协调服务器**不转发任何用户数据**。协调服务器暂时不可用时，已经建立的连接仍可继续通信，但无法加入新房间或发现新上线的设备。

默认协调服务器地址：

```text
https://coord.msst-net.msst2031.cn
```

## 中转服务器

中转服务器只做一件事：在设备之间**原样转发**已经加密的数据包。

- 中转服务器看不到通信内容（数据经 WireGuard 端到端加密）
- 中转服务器能看到设备 ID、公网地址、流量大小与时序
- 游戏发现数据也经过中转服务器分发，它只投递给同一房间内、身份经过验证的成员

中转服务器分为两类：

| 类型 | 说明 |
|---|---|
| 官方中转 | 由 MSST-Net 运营，出现在协调服务器公布的中转列表中，所有设备都可以自动选用 |
| 自托管中转 | 由任何人自行部署，不公开列出，只能由房主在建房时通过连接串指定为**房间中转** |

详见：

- [《连接机制》](/connect/basics/connections)
- [《房间中转》](/connect/spaces/room_relay)
- [《自托管中转服务器》](/connect/selfhost/relay)
